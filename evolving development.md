- this project is evolving
- I did not have a clear and totally mapped out vision for this
- it has moved and been reshaped as I used it. I've also learned by using versions of it
- I think we are creeping up on a very cohesive app that will be very useful with the target audience
- I think we will end up with a better product in the end as a result of this process
- maybe someone with more skill could have arrived at the same ends in a quicker more cost effective process than what we've taken with this project. I don't know
- I've developed products, lead project teams to develop features within product lines, and developed small features on my own - this process is different!
- I think, for multiple reasons, you have to be willing to go back and revise certain decisions and implementation details. As the picture of this product becomes clearer I see some implementation details as obviously wrong. I also see needed features and some redundant features.
- these revisions cost time and compute resources. They have not been painful in terms of my work effort because I'm not writing the code. The only part  that is a bit tedious is the retesting although we have been adding to the regression test library as we proceed which helps catch issues without my manual testing.
- having a mindset that is always looking for improvement and new features to enhance the product by building on it's existing functionality really fits this development process.
